# v0.10.1 — 2026-09-25

> **화면 사이 손잡이.** v0.10.0 으로 다섯 화면이 브라우저에 들어왔지만, 화면을 옮길 때마다 같은 경로를 손으로 다시 쳐야 했습니다. 이번 버전은 그걸 잇습니다 — 미리보기에서 맞춘 레시피가 일괄 생성으로, 결함 표시에서 넣은 조각이 보관함으로, 보관함의 조각이 다시 결함 표시로 **버튼 하나에** 넘어갑니다. 합성 알고리즘·레시피 스키마·출력은 바뀌지 않았고, 런타임 의존성도 여전히 넷입니다.

## 새로 생긴 것

- **미리보기 → 일괄 생성: `일괄 생성으로 보내기`** — 지금 맞춰 둔 레시피를 저장하고, 일괄 생성 화면이 그대로 이어받습니다(출력 폴더·장수·시드·형식까지 채워진 채로). 저장까지 함께 하는 이유는 화면에 보이는 `anograft run <레시피>` 한 줄이 **실제로 돌아가야 하기 때문**입니다. 저장만 하고 싶으면 `레시피만 저장` 이 그대로 있습니다.
- **결함 표시 → 결함 보관함: 저장이 바로 보입니다** — 조각을 보관함에 넣으면 보관함 화면이 **열어 보기만 해도** 새 조각을 보여 줍니다. 저장 직후 `결함 보관함에서 보기 →` 버튼으로 바로 넘어갈 수도 있습니다.
- **결함 보관함 → 결함 표시: `다듬기`** — 마스크가 엉성한 조각을 골라 누르면 그 크롭과 지금 마스크가 결함 표시에서 열립니다. 고쳐서 저장하면 **같은 조각을 덮어씁니다**(새 조각이 생기지 않습니다). 기존 창의 "라벨 탭에서 다듬기" 와 같은 길이라 결과도 같습니다.
- **열기 칸의 최근 경로** — 다섯 화면의 경로 칸에서 최근에 연 것을 고를 수 있습니다. 종류가 **칸의 뜻**으로 나뉘어 있어서(보관함 · 결함 사진 · 레시피 · 출력 폴더), 미리보기에서 저장한 레시피가 일괄 생성 칸 목록에도 그대로 뜨고, 일괄 생성의 출력 폴더가 검수 칸에 뜹니다.

## 바뀐 것

- 웹 결함 표시의 `전부 지우기` 가 기존 창과 같은 동작을 쓰도록 맞췄습니다 — 예전에는 지우기가 기록에 흔적을 남겨 저장된 조각의 `mask_origin` 이 기존 창과 달라질 수 있었습니다.

## 알아 둘 것

- **조각을 다듬어 저장하면 되돌릴 수 없습니다.** 마스크를 덮어쓰고, 박스에서 추정한 신뢰도 점수는 지워집니다(사람이 직접 손봤다는 뜻이므로). 조각 자체를 없애려면 보관함에서 삭제하세요 — 빈 마스크로는 덮어쓸 수 없습니다.
- **최근 경로는 `~/.anograft/recent.json` 에 저장됩니다.** 종류별로 최대 10개이고, 경로 문자열만 들어갑니다. 파일을 지워도 되고, 다른 곳에 두고 싶으면 환경변수 `ANOGRAFT_HOME` 으로 폴더를 바꿀 수 있습니다. 홈 폴더에 쓸 수 없는 PC 에서도 화면은 평소처럼 돕니다(기억만 안 할 뿐).
- 일괄 생성이 **돌고 있는 동안에는** 미리보기에서 보내기가 거절됩니다. 진행 중인 실행의 설정이 발밑에서 바뀌면 화면이 잘못된 것을 설명하게 되기 때문입니다.

## English

> **Handoffs between screens.** v0.10.0 put all five screens in the browser, but moving between them still meant retyping the same paths. This release wires them together — the recipe you tuned in Preview goes to Batch, the crop you labelled goes to the Bank, and a crop in the Bank goes back to Labeling, each with one button. Synthesis algorithms, recipe schema and outputs are unchanged, and the runtime dependencies are still just four.

## New

- **Preview → Batch: "Send to batch"** — saves the recipe you have tuned and hands it straight to the Batch screen, settings filled in. It saves as part of the handoff because the `anograft run <recipe>` line shown on screen has to actually work. "Save recipe only" is still there if that is all you want.
- **Labeling → Bank: saves show up immediately** — after you add a crop to the bank, the Bank screen shows it as soon as you open it. A `View in defect bank →` button takes you there straight after saving.
- **Bank → Labeling: "Touch up"** — pick a crop with a sloppy mask and it opens in Labeling with its current mask. Saving **overwrites that same crop** instead of adding a new one, along the same path as the desktop window's equivalent.
- **Recent paths in the open fields** — each of the five screens offers what you opened recently. Kinds are split by **what the field means** (bank, defect photo, recipe, output folder), so a recipe saved in Preview also appears in the Batch field, and a batch output folder appears in Review.

## Changed

- Web Labeling's "Clear all" now behaves exactly like the desktop window's — previously it left a trace that could make a saved crop's `mask_origin` differ between the two.

## Notes

- **Touching up a crop cannot be undone.** It overwrites the mask and clears the box-estimated confidence score (a human has looked at it now). To remove the crop itself, delete it in the Bank — an empty mask is rejected.
- **Recent paths live in `~/.anograft/recent.json`** — at most 10 per kind, path strings only. You can delete the file, or point `ANOGRAFT_HOME` somewhere else. On a machine where the home folder is not writable the screens work as usual; they just do not remember.
- While a batch run is in progress, sending from Preview is refused — changing an in-flight run's settings would make the screen describe the wrong thing.

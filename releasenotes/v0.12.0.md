# v0.12.0 — 2026-09-27

> **루프가 보입니다.** v0.11.0 으로 학습 루프는 돌기 시작했지만, 지금 어디까지 왔는지는 터미널에서 `anograft loop status` 를 쳐야 알 수 있었습니다. 이번 버전은 그걸 **브라우저 화면 하나**로 옮깁니다 — `anograft serve` 의 여섯 번째 화면 **⑥ 학습 루프**입니다. 현재 모델, 이 라운드의 단계, 왜 도는지/안 도는지, 라운드 기록을 한눈에 보고, **사람이 판정할 차례면 버튼 하나로 검수 화면이 그 폴더를 엽니다.**
>
> **합성 알고리즘·레시피 스키마·출력 형식은 바뀌지 않았습니다.** 런타임 의존성도 여전히 넷(numpy · opencv-python-headless · pydantic · pyyaml)이고, 루프를 쓰지 않으면 이 화면은 "설정 파일을 여세요" 안내만 띄웁니다 — 나머지는 v0.11.0 과 똑같이 동작합니다.

## 새로 생긴 것

### ⑥ 학습 루프 화면 — `anograft serve` → 학습 루프

- **지금 어디인가**를 한 화면에서 봅니다: 현재 모델(champion)과 지난 라운드 대비 증감 · 이 라운드의 **단계 줄**(끝난 것 · 지금 것 · 남은 것) · 결함 보관함 조각 수 · **사람 수정률**(모델 초안 중 사람이 다듬은 비율 — 분모가 없으면 0% 가 아니라 "모름"입니다).
- **라운드별 점수 추이**. 기준선 재설정(`loop baseline-reset`)·자동 정지 해제(`loop breaker-reset`) 지점 앞뒤로는 **선을 잇지 않습니다** — 그 구간은 애초에 견주지 않기로 한 자리라, 이어 그리면 화면이 "떨어졌다/올랐다"는 거짓말을 합니다. 점수가 없는 라운드(학습 전에 멈춘 라운드)는 점을 찍지 않습니다.
- **다음 라운드 조건**: 트리거가 지금 돌 때라고 하는지와 그 이유 · 자동 정지가 걸렸는지(또는 무엇을 감시 중인지) · 마지막 `loop tick` 이 언제 왔고 돌았는지 · 이미 스코어링한 이미지 수 · 지금 도는 실행이 있는지.
- **보관함 분포** — 클래스별 조각 수와 **마지막 라운드 이후 늘어난 수**, 비중. 미분류(`__unsorted__`)는 맨 끝에 따로 보입니다(합성·학습 출력에서 빠지는 자리 그대로).
- **라운드 기록** — `rounds.jsonl` 한 줄이 표 한 행입니다: 끝난 때 · 점수 · 편입한 조각 · 보관함 조각 수 · 사람 수정률 · 설정 지문(`pipeline_hash`) · 결과(승급/유지/기준선 재설정).
- **검토 대기로 가기 →** — 사람이 판정할 차례면 이 버튼이 **⑤ 검수 화면을 그 라운드의 검토 대기 폴더로 열어 줍니다**. 판정하고 `anograft loop run` 을 다시 부르면 그 자리에서 이어 갑니다.

### 라운드는 화면에서 돌리지 않습니다 — 그게 설계입니다

한 바퀴는 학습기를 별도 프로세스로 띄워 몇 시간을 돌 수 있는 일이고, 그 자리는 이미 **`anograft loop run`**(사람이 직접) 과 **`anograft loop tick`**(스케줄러가 부름) 입니다. Graft 는 상주 프로세스가 되지 않습니다. 그래서 이 화면은 **보여 주고 넘겨 주는 일**만 하고, 지금 쳐야 할 명령을 그대로 보여 줍니다(그대로 복사해 쓰시면 됩니다). 자동 정지 해제·기준선 재설정처럼 **"무엇을 바꿨는지"를 적어야 하는 조작**도 CLI 에 그대로 둡니다 — 그 메모가 라운드 기록에 남아야 나중에 설명이 됩니다.

## 바뀐 것

- **릴리스 워크플로에서 PyPI 게시를 뺐습니다**(배포 여부를 더 검토합니다). 설치는 그대로 **Windows zip**(Release 자산) 또는 `pip install "anograft[gui] @ git+https://github.com/slnu21/Graft.git"` 입니다.
- 열기 칸의 **최근 경로**에 루프 설정(`loop.yaml`) 종류가 생겼습니다 — 레시피 목록과 섞이지 않습니다.
- 시작 화면의 "다음에 할 일"에 검수·학습 루프 줄이 실제 화면을 가리키도록 고쳤습니다.

## 알아 둘 것

- **루프는 선택입니다.** `loop.yaml` 이 없으면 ⑥ 화면은 안내만 띄우고, 나머지 다섯 화면과 CLI 는 그대로입니다.
- **화면은 매번 디스크에서 읽습니다.** 루프는 스케줄러·명령줄에서도 돌기 때문에 화면이 상태를 들고 있으면 옛 라운드를 보여 주게 됩니다. 라운드가 도는 중(잠금이 잡힌 동안)에만 3초마다 따라가고, 그 밖에는 새로고침할 때 읽습니다.
- **아직 없는 것**: 고정/최근 **이중 평가셋** 비교와 클래스별 점수 기여는 이 화면에 없습니다 — 그 데이터를 만드는 기능(롤링 평가셋)이 아직 없어서, 지금 그리면 없는 숫자를 그리게 됩니다.

# v0.12.0 — 2026-09-27 (English)

> **The loop is now visible.** v0.11.0 made the training loop run; seeing where it stood still meant typing `anograft loop status` in a terminal. This release moves that into **one browser screen** — the sixth screen of `anograft serve`: **⑥ Training loop**. Current model, this round's phases, why it is (or isn't) running, and the round history at a glance — and when it's **your turn to judge, one button opens the review screen on that queue folder**.
>
> **Synthesis algorithms, recipe schema and output formats are unchanged.** Still four runtime dependencies (numpy, opencv-python-headless, pydantic, pyyaml), and without a `loop.yaml` the new screen simply tells you how to make one — everything else behaves exactly as in v0.11.0.

## New

### ⑥ Training loop screen — `anograft serve` → 학습 루프

- **Where you are**, in one place: the champion model and its change from the previous round; this round's **phase strip** (done / current / remaining); bank piece count; and the **human correction rate** (share of model drafts a person refined — with no denominator it reads "unknown", not 0%).
- **Score trend per round.** The line **breaks** at a baseline reset (`loop baseline-reset`) or a breaker reset (`loop breaker-reset`) — those spans are deliberately not compared, so joining them would make the chart lie. Rounds without a score (stopped before training) get no point.
- **Next-round conditions**: whether the trigger says it's time and why; whether the circuit breaker tripped (or what it is watching); when the last `loop tick` arrived and whether it ran; how many images have already been scored; and whether a run holds the lock right now.
- **Bank distribution** — pieces per class, **how many arrived since the last round**, and each share. Unsorted (`__unsorted__`) stays last, as it does everywhere else.
- **Round history** — one `rounds.jsonl` line per table row: finished at, score, intake, bank pieces, correction rate, pipeline hash, outcome (promoted / kept / baseline reset).
- **Go to the review queue →** — when it's your turn, this opens the **review screen on that round's queue folder**. Judge, then call `anograft loop run` again and it resumes from there.

### Rounds are not started from the screen — by design

A round can spawn a trainer process for hours, and the place for that is already **`anograft loop run`** (you) and **`anograft loop tick`** (your scheduler). Graft never becomes a resident process. So this screen only **shows and hands off**, printing the exact command to run. Operations that must record *what you changed* — clearing the breaker, resetting the baseline — also stay in the CLI, because that note belongs in the round ledger.

## Changed

- **PyPI publishing was removed from the release workflow** (we are still deciding). Install from the **Windows zip** (Release asset) or `pip install "anograft[gui] @ git+https://github.com/slnu21/Graft.git"`.
- Recent-path lists now have a kind for the loop config (`loop.yaml`), kept apart from recipes.
- The start screen's "what's next" list now points at the actual review and loop screens.

## Good to know

- **The loop is optional.** Without `loop.yaml` the new screen shows guidance only; the other five screens and the CLI are unaffected.
- **The screen reads from disk every time.** The loop also runs from a scheduler or the command line, so a cached view would show a stale round. It follows along every 3s only while a round holds the lock; otherwise it reads when you refresh.
- **Not there yet**: fixed vs. rolling eval-set comparison and per-class score contribution. The feature that produces that data (rolling eval set) does not exist yet, and drawing it now would mean drawing numbers we don't have.

# v0.11.0 — 2026-09-26

> **루프가 닫힙니다.** 지금까지 Graft 는 "데이터를 만드는 도구"였습니다. 이번 버전은 그 데이터가 **모델을 학습시키고, 그 모델이 현장 이미지에서 볼 것을 골라 오고, 사람이 판정한 것이 다시 결함 보관함으로 들어오는** 한 바퀴를 명령 하나로 엮습니다(`anograft loop run`). 스케줄러(Windows 작업 스케줄러·cron)가 `anograft loop tick` 을 부르면 새로 들어온 사진만 보고 한 바퀴 돌고 끝납니다 — Graft 는 상주 프로세스가 되지 않습니다.
>
> **합성 알고리즘·레시피 스키마·출력 형식은 바뀌지 않았습니다.** 기존 명령(`run`·`preview`·`bank`·`serve`)은 그대로이고, 루프를 쓰지 않으면 이번 버전은 v0.10.1 과 똑같이 동작합니다. 런타임 의존성도 여전히 넷(numpy · opencv-python-headless · pydantic · pyyaml)입니다 — 학습기는 **별도 환경에서 프로세스로** 부릅니다.

## 새로 생긴 것

### 한 바퀴 — `anograft loop run` · `loop tick` · `loop status`

- **라운드 하나가 이렇게 돕니다**: 배포 모델이 현장 이미지 스코어링 → **검토 대기** 고르기 → *[사람이 검수 화면에서 판정]* → 채택분 결함 보관함 편입 → 합성 → 재학습·평가 → 승급 판정. 사람이 판정할 차례가 되면 **멈추고 무엇을 해야 하는지 알려 줍니다**.
- **멱등합니다.** 다시 부르면 남은 단계부터 이어 갑니다 — 학습이 세 시간 뒤 실패해도 **합성을 다시 하지 않습니다**.
- 설정은 레시피 밖 **`loop.yaml`** 하나(예시 `loop.example.yaml`)입니다. 레시피는 공유되는 물건이라 현장 폴더·평가셋 같은 개인 환경을 넣지 않습니다. 경로는 **`loop.yaml` 파일 기준**이라 스케줄러가 어느 폴더에서 불러도 같은 라운드를 가리킵니다.
- `anograft loop status` 가 지금 어디인지 한 화면에 보여 줍니다 — 현재 모델 · 다음 단계 · 최근 라운드 · 처리 이력 · 지금 돌 때인지.

### 검토 대기 — 볼 것만 추려 줍니다

- `anograft loop queue` 가 예측에서 **사람이 볼 것만** 골라 한 폴더로 냅니다. 순서는 **두 모델이 엇갈린 것 → 경계(임계값 근처) → 확신 → 무작위** 입니다. 엇갈린 것이 먼저인 이유는 서로 다른 방식의 모델은 **틀리는 방식도 달라서** 그 자리에 정보가 가장 많기 때문입니다.
- **새 포맷을 만들지 않았습니다.** 그 폴더는 검수 화면이 **그대로 엽니다**(`anograft serve` → 검수, 또는 기존 창의 검수 탭). 판정도 원래 쓰던 채택/반려 그대로이고, `anograft loop accept` 가 채택분만 보관함에 넣습니다.
- 모델이 그린 마스크는 **추정으로 표시**됩니다(`mask_origin: pred:<학습기>`). 사람이 다듬으면 `manual:*` 이 되고, 그 비율이 아래 **사람 수정률**입니다.

### 같은 사진을 두 번 보지 않습니다 — 처리 이력과 동시 실행 잠금

- 현장 폴더에 사진이 계속 쌓여도 **이미 점수를 매긴 것은 건너뜁니다**(`<출력>/processed.jsonl`). 이름을 바꿔 복사해 온 사진도 같은 이미지로 봅니다. 다시 보게 하려면 `loop tick --since <라운드>`.
- 앞 실행의 학습이 세 시간째 도는 중에 스케줄러가 또 불러도 라운드 폴더가 섞이지 않습니다. 이때 `loop tick` 은 **오류가 아니라 "다음에"**(종료 코드 0)로 답합니다 — 5분마다 실패 알림이 오는 운영은 아무도 보지 않기 때문입니다.

### 라운드 기록 — "라운드 3의 모델은 무슨 보관함으로 학습됐나"

- `<출력>/rounds.jsonl` 에 **더하기만** 합니다: 라운드 시작·단계·끝(점수·승급·현재 모델·재현 해시·보관함 스냅샷)·**실패 사유**·안 돈 사유. 사람이 읽을 수 있는 한 줄씩이고, 되돌리기는 현재 모델 포인터를 옛 라운드로 돌리는 일입니다.
- 라운드마다 **보관함 스냅샷**(복사가 아니라 번호·지문 목록)을 남겨 그 라운드가 실제로 쓴 조각을 나중에 대조할 수 있습니다.
- **언제 도나**는 `loop.yaml` 의 `trigger` 가 정합니다(새 조각 N개 · 새 사진 N장 · 최소 간격 · 최대 간격). 기본값은 제한 없음이고, 켜면 **안 돈 이유가 항상 남습니다**.

### 처음 보는 형상 → 미분류

- 보관함 어느 조각과도 닮지 않은 결함은 **검토 대기의 맨 앞**으로 옵니다. 채택하면 **이름 없이 미분류**로 들어갑니다 — 틀린 이름은 그 클래스를 조용히 오염시켜 되돌릴 수 없지만, 미분류는 **`anograft bank promote <보관함> --to <클래스>`** 한 줄로 이름을 줍니다.
- 미분류는 합성·학습 출력에서 빠지고 **클래스 목록의 맨 끝**에 고정돼 기존 모델의 클래스 번호를 밀지 않습니다.
- **클래스를 새로 만들면 라운드가 멈춥니다.** 평가셋에 그 클래스의 정답이 없으면 모델이 **잘 잡을수록 헛검출로 집계되어 점수가 떨어지고** 라운드 비교가 끊깁니다. 평가셋을 손본 뒤 **`anograft loop baseline-reset --note …`** 으로 지점을 남기면 그 뒤 첫 라운드는 점수를 견주지 않습니다.

### 자동 정지 — 망가진 루프는 망가진 채로 계속 돕니다

- 세 가지를 보고 **새 라운드를 열지 않습니다**: ① 몇 라운드째 승급 없음(데이터를 더 넣어서는 나아지지 않는다는 뜻 — 조명·해상도·모델을 볼 때입니다) ② **사람 수정률**이 바닥(모델이 그린 마스크를 아무도 다듬지 않는 상태 = 모델이 좋아진 게 아니라 **아무도 안 보고 있는** 것일 수 있습니다) ③ 보관함 클래스 **분포 급변**(로트·공정이 바뀌었는지 확인할 때).
- 기준은 `loop.yaml` 의 `breaker` 에서 정하고 **기본값은 전부 제한 없음**이라 켜지 않으면 지금까지처럼 돕니다. 멈춘 것은 실패가 아니라 신호이므로 푸는 길은 하나입니다 — **`anograft loop breaker-reset --note "무엇을 바꿨는지"`**(라운드 기록에 남습니다).
- 진행 중인 라운드는 막지 않습니다(사람이 판정해 둔 검토 대기가 썩지 않게).

### 학습기는 별도 환경에서 — `anograft trainer`

- `trainer list`·`trainer info` 로 등록된 학습기와 쓸 수 있는지를 보고, `trainer fit`·`trainer predict` 로 계약대로 부릅니다. 등록은 레시피 밖 **`trainers.yaml`**(예시 `trainers.example.yaml`)이고, 학습기는 **자기 venv 에서 프로세스로** 돌기 때문에 Graft 의 의존성이 늘지 않습니다.
- 어댑터 셋이 함께 들어 있습니다: `adapters/yolo.py`(ultralytics 검출) · `adapters/anomalib_trainer.py`(PatchCore·PaDiM·FastFlow 등 — **정상만 학습**한다고 스스로 밝히므로 루프가 합성 결함을 학습셋에 넣지 않습니다) · `adapters/noop.py`(표준 라이브러리만 쓰는 더미 — 학습 환경 없이 루프 전체를 시험할 수 있습니다).

### 평가셋은 코드가 지킵니다

- `<보관함>/holdout.txt` 에 적힌 사진은 **보관함이 거부합니다**(임포트·라벨 저장·루프 편입 모두 한 지점에서). 몇 건을 왜 뺐는지 요약에 찍히고, 목록을 나중에 만든 경우는 `anograft bank verify` 가 알려 줍니다. 자동 루프에서 평가셋이 학습으로 새면 성능 숫자가 **조용히 무의미해지기** 때문입니다.
- `anograft bank snapshot` / `bank verify` — 라운드 재현용 조각 목록(복사가 아니라 번호·지문)과 대조.

## 바뀐 것

- 라운드 이력이 `loop.state.json` 에서 **`rounds.jsonl`** 로 옮겨졌습니다(`loop status` 의 출력은 그대로).
- 검토 대기를 고를 때 **몫 하나가 비면 경계 순서로 채웁니다** — 임계값을 넘긴 검출이 하나도 없는 초기 라운드에서 큐가 요청한 장수보다 작게 나오던 것을 고쳤습니다.
- 추정 마스크 판정을 한 곳으로 모았습니다(`yolo-box:*` · `pred:*`) — `bank ls` 의 `est`, 보관함 타일, `bank preview` 테두리가 같은 답을 냅니다.

## 알아 둘 것

- **루프는 선택입니다.** `loop.yaml` 을 만들지 않으면 이번 버전은 v0.10.1 과 똑같이 동작합니다. 루프를 쓰려면 학습기를 따로 설치해야 합니다(별도 venv 권장 — Graft 코어에 torch 를 넣지 않는 이유).
- **루프가 만드는 학습 데이터셋 형식은 아직 `yolo`·`pairs` 둘입니다.** 학습기가 다른 형식을 요구하면 데이터를 만들기 **전에** 알려 줍니다.
- **비지도(정상만 학습) 학습기로는 아직 라운드를 돌리지 않습니다** — 평가에는 쓸 수 있습니다(`trainer fit`·`tools/bench_model_rank.py`). 합성 결함을 정상 분포 학습셋에 넣으면 오염이기 때문이고, 루프의 비지도 경로는 다음 단위입니다.
- **자동 정지·다음 라운드 조건의 임계값은 현장마다 다릅니다.** 그래서 코드 기본값은 전부 "제한 없음"이고 실무 제안은 `loop.example.yaml` 주석에 적어 두었습니다(연속 3회 · 사람 수정률 0.05 · 분포 변화 0.35 · 새 조각 20개 · 7일).
- 검출만 하는 학습기(박스 라벨)의 검토 대기에는 **마스크가 없습니다** — 채택해도 보관함에 못 들어가고 "결함 표시 화면에서 그리세요"로 안내합니다. 세그멘테이션 가중치나 비지도 이상 지도를 함께 주면 마스크가 생깁니다.

## English

> **The loop closes.** Until now Graft was a tool for *making* data. This release wires that data into one round you can run with a single command (`anograft loop run`): the deployed model scores field images, the loop picks what a human should look at, the crops you accept go back into the defect bank, and the next model is trained and judged against a frozen eval set. A scheduler (Task Scheduler, cron) calls `anograft loop tick`, which looks only at newly arrived photos, runs one round and exits — Graft never becomes a resident process.
>
> **Synthesis algorithms, recipe schema and output formats are unchanged.** If you do not use the loop, this release behaves exactly like v0.10.1, and the runtime dependencies are still four (numpy, opencv-python-headless, pydantic, pyyaml) — trainers run as separate processes in their own environments.

## New

### One round — `anograft loop run` · `loop tick` · `loop status`

- A round runs: score field images → pick a **review queue** → *[you judge in the Review screen]* → accepted crops into the defect bank → synthesize → retrain and evaluate → promote or keep. When it is your turn, it **stops and tells you what to do**.
- **Idempotent.** Call it again and it continues from the next unfinished step — if training fails three hours in, synthesis is not redone.
- Configuration lives in one file outside the recipe: **`loop.yaml`** (see `loop.example.yaml`). Recipes are meant to be shared, so field folders and eval sets do not belong in them. Paths resolve **relative to `loop.yaml`**, so a scheduler can call it from anywhere.
- `anograft loop status` shows where you are: current model, next step, recent rounds, processed images, and whether it is time to run.

### Review queue — only what is worth looking at

- `anograft loop queue` turns predictions into one folder of items, ordered **disagreement → boundary → confident → random**. Disagreement comes first because models built differently also *fail* differently, so that is where the information is.
- **No new format.** The Review screen opens that folder as-is (`anograft serve` → Review, or the desktop Review tab), accept/reject works as before, and `anograft loop accept` imports only what you accepted.
- Model-drawn masks are marked as estimates (`mask_origin: pred:<trainer>`); once a human touches one it becomes `manual:*`, and that ratio is the **human correction rate** below.

### The same photo is never scored twice — processed log and a run lock

- Photos can keep piling up in the field folder; already-scored ones are skipped (`<out>/processed.jsonl`), including copies renamed along the way. `loop tick --since <round>` re-examines them.
- If the previous run's training is still going, a second call does not interleave round folders. `loop tick` answers **"not now" (exit 0), not an error** — nobody reads a failure alert that arrives every five minutes.

### Round ledger — "which bank trained round 3's model?"

- `<out>/rounds.jsonl` is **append-only**: round start, steps, end (metric, promotion, current model, reproduction hash, bank snapshot), **failures**, and reasons for not running. Rollback is moving the current-model pointer back to an older round.
- Each round records a **bank snapshot** (an id + fingerprint list, not a copy) so you can tell exactly which crops it used.
- **When to run** is decided by `trigger` in `loop.yaml` (N new crops, N new photos, minimum and maximum interval). The default is no limit, and when enabled, the reason for *not* running is always recorded.

### Shapes you have not seen before → unsorted

- A defect that resembles nothing in your bank goes to the **front of the review queue**, and accepting it files it **without a name** under unsorted — a wrong label quietly poisons that class and cannot be undone, while unsorted is one line to fix: **`anograft bank promote <bank> --to <class>`**.
- Unsorted crops are excluded from synthesis and training output, and pinned to the **end of the class list** so existing class ids never shift.
- **Creating a new class stops the round.** With no ground truth for it in the eval set, the better the model finds it, the more it counts as false positives — the round-to-round comparison breaks. Fix the eval set, then record the break with **`anograft loop baseline-reset --note …`**; the next round is not compared against the old score.

### Circuit breaker — a broken loop keeps running, broken

- Three conditions stop a new round from opening: ① no promotion for N rounds (more data will not help — look at lighting, resolution, the model) ② the **human correction rate** bottoming out (nobody is touching up the model's masks: that may mean nobody is looking, not that the model got good) ③ a sharp shift in the bank's class distribution (has the lot or process changed?).
- Thresholds live in `breaker` in `loop.yaml` and default to **no limit**. Stopping is a signal, not a failure, so there is exactly one way to resume: **`anograft loop breaker-reset --note "what you changed"`** (recorded in the ledger).
- A round already in progress is never blocked — a queue you already judged must not rot.

### Trainers run in their own environment — `anograft trainer`

- `trainer list` / `trainer info` show which trainers are registered and usable; `trainer fit` / `trainer predict` call them by contract. Registration lives outside recipes in **`trainers.yaml`** (see `trainers.example.yaml`), and trainers run as processes in their own venv, so Graft's own dependencies do not grow.
- Three adapters ship with it: `adapters/yolo.py` (ultralytics detection), `adapters/anomalib_trainer.py` (PatchCore, PaDiM, FastFlow and friends — they declare that they train on normal images only, so the loop never feeds them synthetic defects), and `adapters/noop.py` (standard-library-only dummy, so you can exercise the whole loop without a training environment).

### The eval set is protected by code

- Photos listed in `<bank>/holdout.txt` are **refused by the bank** at a single point (importers, label saves, loop intake), with a summary of how many were skipped and why; `anograft bank verify` catches lists written after the fact. In an automated loop, an eval-set leak makes your numbers **quietly meaningless**.
- `anograft bank snapshot` / `bank verify` — per-round crop lists (ids and fingerprints, not copies) and comparison.

## Changed

- Round history moved from `loop.state.json` to **`rounds.jsonl`** (`loop status` output is unchanged).
- When one share of the review queue comes up empty, it is filled in boundary order — early rounds with no detections above threshold used to return fewer items than requested.
- Estimated-mask detection is decided in one place (`yolo-box:*`, `pred:*`), so `bank ls`, bank tiles and `bank preview` borders agree.

## Notes

- **The loop is optional.** Without a `loop.yaml`, this release behaves exactly like v0.10.1. Using it means installing a trainer yourself (a separate venv is recommended — that is why torch is not in Graft's core).
- **The loop assembles `yolo` and `pairs` datasets only** so far; a trainer that wants another format is refused *before* any data is made.
- **Unsupervised (normal-only) trainers cannot drive a round yet** — you can still evaluate with them (`trainer fit`, `tools/bench_model_rank.py`). Feeding synthetic defects into a normal-distribution training set is contamination; the unsupervised path is the next unit.
- **Breaker and trigger thresholds are site-specific**, so every default is "no limit" and the practical suggestions sit in `loop.example.yaml` comments (3 rounds, 0.05 correction rate, 0.35 distribution shift, 20 new crops, 7 days).
- A detection-only trainer's queue has **no masks** — accepting those does not import them; you are told to draw them in the Labeling screen. Segmentation weights or an unsupervised anomaly map provide masks.
